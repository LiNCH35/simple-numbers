# Simple Numbers

Экспериментальный инструмент для исследования простых чисел: изолированное ядро на чистом JavaScript (Node + браузер), CLI для генерации и анализа последовательностей и веб-приложение на Vue 3 с GPU-ускорением через WebGL.

## Обзор

Приложение генерирует «псевдопростые» последовательности на основе вероятностной модели: для текущей последовательности вычисляется вероятность `P` того, что случайное целое число не делится ни на одно из её чисел (формула включения-исключения). Эта вероятность отслеживается как наблюдаемая величина, а генерация следующего числа идёт по калибровке Крамера — плотности `1/ln x` (режимы `jump`/`step`). Псевдопростые принимаются без проверки на простоту — расхождение с настоящими простыми числами (`π(x)`) анализируется по графикам и таблицам разниц.

## Возможности

- **Ядро без зависимостей** (`src/core/*.mjs`): одно и то же вычислительное ядро работает в Node (CLI) и в браузере
- **Генерация последовательностей**: калибровка Крамера — `jump` (экспоненциальные скачки со средним `ln x`, дискретизация `round`/`floor`) и `step` (кандидат +1 принимается с вероятностью `1/ln x`), опциональный twin-буст Харди–Литтлвуда для `step`; исследовательские регуляторы `twinRate`/`gapShape` (инъекция близнецов `κ/ln x` и гамма-сгущение `var/mean² = 1/k`, jump-режим), `lattice6` (решёточная связка: класс ±1 mod 6, инъекция близнецов только из вычета 5) и `lattice30` (решётка mod 30, инъекция только из twin-классов 29/11/17, перенаправление кратных 3 и 5)
- **Воспроизводимость**: детерминированный PRNG (splitmix32) — результат однозначно определяется seed (поле `Seed` в UI и `--seed` в CLI)
- **Генерация в Web Worker**: UI не блокируется, Stop срабатывает мгновенно; при недоступности воркера — откат на main-thread с тем же splitmix32
- **Сравнение с реальными простыми**: сегментированное решето (`src/core/real-primes.mjs`) — в UI тумблер `Compare with real primes` (кривые `count ≤ x` модели и π(x) на одном графике + twinIndex/meanGap/mod6 реальных рядом с модельными), в CLI `scripts/compare-model-reality.mjs` — отчёт «модель vs реальность»
- **CLI**: команды `generate`, `probability`, `diff`, `bench` с выводом в `text`, `json` или `csv`
- **Веб-интерфейс**: двухпанельный layout, статистика в реальном времени, прогресс генерации, графики распределения разниц (по последовательностям + средний)
- **GPU-ускорение**: WebGL-кернелы (gpu.js) с автоматическим откатом на CPU при любой ошибке

## Математическая основа

### Вероятность (включение-исключение)

Для последовательности простых `p₁, p₂, …, pₙ`:

```
P = 1 − Σ(±1 / (p₁ × p₂ × … × pₖ))   по всем непустым подмножествам
```

Знак слагаемого определяется мощностью подмножества: нечётная — плюс, чётная — минус. Пример для `{2, 3}`:

```
P = 1 − (1/2 + 1/3 − 1/(2×3))
```

### Оптимизации вычисления суммы

- **Компенсированное суммирование Ноймайера**: слагаемые порядка `1e-16` не теряются при накоплении суммы
- **Отсечение по tolerance**: подмножество пропускается, как только произведение превышает `limit = 1 / tolerance` (вклад меньше tolerance); счётчик пропусков доступен как `skipped`
- **Ограничение sensitivity**: опциональный предел мощности подмножеств в слагаемых (по умолчанию не ограничен)
- **Бюджеты комбинаций**: `maxCombinations` — общий предохранитель; `maxCombinationsPerPrime` (30 000 000) — лимит на одно добавленное число. При срабатывании добавление помечается `lastAddTruncated`, а UI показывает предупреждение о сниженной точности

### Генерация последовательности

- `splitmix32(seed)` — детерминированный PRNG
- **jump**: экспоненциальный промежуток со средним `ln x` (Крамер); при `--jump-gap floor` — `1 + floor(Exp(ln x − 1/2))`, при `round` (по умолчанию) — `max(1, round(Exp(ln x)))`
- **step**: кандидат `+1` принимается, если `random() < 1/ln(x)`
- **twin-bias** (`--twin-bias`, только step): вероятность кандидата `+2` усиливается множителем `2C₂ ≈ 1.32` с компенсацией плотности
- Вероятность включения-исключения `P` параллельно обновляется по мере генерации (отключается `--no-track-probability`)
- Начальная последовательность: `[2, 3]`; числа принимаются как «псевдопростые» без проверки простоты

### Эталон π(x)

Для сравнения используется решето Эратосфена (`primeCountPrefix`, `Uint32Array` + `Uint8Array`) — решето применяется **только** к эталонным количествам простых, не к псевдопростым.

## Эксперимент: отклонение псевдопростых от π(x)

### Методология

`node scripts/run-experiment.mjs` прогоняет матрицу последовательностей и сохраняет rich JSON (sequence + points разниц + статистика) в `results/`; скрипт возобновляем — готовые прогоны пропускаются. `node scripts/analyze-results.mjs` группирует прогоны по режиму, выравнивает общую сетку x и считает среднюю кривую разниц ±σ по seeds, регрессионный наклон, отклонение от `Li(x)` (`N − Li`) и кросс-режимные сравнения. Итог: `results/analysis.json` + `results/analysis.md`.

Основная матрица — 20 прогонов по 2M @ tolerance 1e-10 (seeds 1–5, xStep 200, `maxCombinations` 5e10): 5×`jump` (round), 5×`jump --jump-gap floor`, 5×`step`, 5×`step --twin-bias`. x до ≈ 32.4M (π(x) ≈ 2.0M), ≈ 1.3 с на прогон. `--quick` прогоняет смоук-матрицу (2×2000, seed 42) для быстрой проверки окружения.

### Ключевой результат

На матрице 2M (splitmix32) откалиброванные режимы воспроизводят π(x) с суб-процентной точностью; остатки систематические, но объяснимые (см. ниже). Для справки: `li(x) − π(x) ≈ +357` при x ≈ 32.4M, `√π(x) ≈ 1414`.

| Режим | Средняя разница (x ≈ 32.43M) | Отклонение | N − Li(x) | σ по seeds vs √π(x) |
| --- | --- | --- | --- | --- |
| `jump` (round) | −3335.60 | **−0.167%** | −3658 | ×1.00 |
| `jump --jump-gap floor` | −475.40 | **−0.024%** | −832 | ×0.98 |
| `step` | +233.40 | **+0.012%** | −116 | ×1.19 |
| `step --twin-bias` | +370.20 | **+0.019%** | +24 | ×1.13 |

### Почему генерация откалибрована: произведение Мертенса, а не 1/ln x

Исходная версия ядра управляла генерацией самой вероятностью P. Включение-исключение сворачивается в точную рекуррентность `P_new = P_prev × (1 − 1/p)`, то есть после накопления множества «простых до x» вероятность модели равна ∏(1 − 1/p). По третьей теореме Мертенса:

```
∏(1 − 1/p) ~ e^(−γ) / ln x ≈ 0.5615 / ln x,   а плотность простых = 1/ln x (ПТС)
```

Модель требует отсутствия делителей среди **всех** накопленных чисел до x, тогда как простота требует лишь отсутствия делителя до **√n** (критерий Лежандра) — избыток жёсткости даёт постоянный множитель e^(−γ) ≈ 0.5615. Замеры подтвердили предсказание: `jump` давал перебор **+17.4%** (равномерный выбор в диапазоне 1/P даёт средний скачок 1/(2P) → плотность ×2), `step` — недобор, растущий с ужесточением tolerance (**−7%** при 1e-10 → **−18%** при 1e-11): отсечение хвоста ряда включения-исключения поднимает P выше Мертенса, поэтому ужесточение tolerance не приближает к π(x), а увеличивает недобор. Поэтому генерация переведена на плотность ПТС `1/ln x` (модель Крамера, 1936), а вероятность P оставлена как наблюдаемая величина.

### Два остаточных дефекта: дискретизация и PRNG

Суб-процентные остатки таблицы объясняются двумя конкретными дефектами, оба видны только на длинных прогонах:

- **`round` + clamp**: дискретизация `max(1, round(Exp(ln x)))` — у экспоненты со средним `ln x ≈ 17` около 2.9% непрерывных значений округляются до нуля, и clamp превращает их в единичные скачки; средний промежуток растёт, наклон регрессии линейный (−1.1e-4 на x). Дельта к несмещённой дискретизации `floor` — **−2834** (−0.14% плотности): −0.167% против −0.024%. У `floor` (`1 + floor(Exp(ln x − 1/2))`) остаток −475 соответствует теоретическому сдвигу дискретизации ≈ 1/(12 ln²x) ≈ 0.03%.
- **PRNG**: у mulberry32 обнаружен частотный дефект — избыток +1190…+1360 ppm в узкой зоне порогов `c ∈ [0.0568, 0.075]` (чисто при `c = 0.5`). Порог `step` `1/ln x` на этом интервале x попадает ровно в дефектную зону (`1/ln x ∈ [0.057, 0.072]`), что давало фиктивный избыток **+2388** — ранее он ошибочно приписывался избытку `Li(x) − π(x)`. На самом деле `li(x) − π(x) ≈ +357`. После перехода на splitmix32: `step` +233, `step --twin-bias` +370.

### Тонкая структура: twin-bias

Чистый Крамер занижает twin-структуру реальных простых (twinIndex ≈ 0.9 против 1.329 у реальных). Опция `--twin-bias` (только `step`) усиливает вероятность кандидата `+2` множителем `2C₂ ≈ 1.3203` с компенсацией плотности `1 + ((C − 1)/ln x)·(1 − 1/ln x)`, чтобы суммарная плотность выживших не менялась. В прогоне 2M: доля промежутка 2 — **7.55%** против 8.19% у реальных, twinIndex **1.226** против 1.329 — буст возвращает большую часть twin-избытка. Полный остаток создают сгущения реальной последовательности (дисперсия промежутков 0.66–0.71 против 1.0 у пуассоновского Крамера). Сравнение `step` против `step --twin-bias` на общей сетке: **+143**.

### Вывод

Калиброванные по ПТС режимы воспроизводят π(x): `step` — с остатком +233 при теоретическом `li − π ≈ +357`, `jump` c `floor` — с недобором −475 порядка 1/(12 ln²x). Разброс по seeds соответствует пуассоновскому √π(x) (×1.0–1.2; сама σ-оценка по 5 сидам имеет ~25% погрешность). Дискретизация `round` оставлена по умолчанию как документированный анти-пример: её −0.167% — чистый эффект clamp'а. Тонкая структура (twins, сгущения) частично восстанавливается `--twin-bias`, но полностью не воспроизводится ни мертенсовской, ни пуассоновской моделями.

## Модель vs реальность

`node scripts/compare-model-reality.mjs` (55 прогонов 2M — 11 режимов × сиды 1–5 — + сегментированное решето до x_max) пишет `results/model-vs-reality.md` — что модель воспроизводит, а что принципиально нет:

| Что | Модель (без корреляций) | Реальные простые |
|---|---|---|
| Плотность на общем отрезке | n vs π(x_max): отклонение ≤ 0.17% | — |
| Нечётные промежутки | ~52% | **0.0%** |
| twinIndex | 0.889 (jump) | **1.328** (асимптота 2C₂ = 1.3203) |
| var/mean² промежутков | 0.95–1.00 (пуассон) | **0.71** (сгущения) |
| drift Δ₄ = π(x;4,3) − π(x;4,1) | −0.22…−0.32 (шум √N) | **+0.284** (bias Чебышёва) |

### Искусственные корреляции: twinRate и gapShape

Ядро (`createGenerator`, jump-режим, используются в compare-model-reality.mjs) имеет два исследовательских регулятора:

- `twinRate` = κ — инъекция близнецов: с вероятностью `min(κ/ln x, 0.9)` промежуток = 2, остальные скачки растягиваются до среднего `(ln x − 2p)/(1−p)` — плотность `1/ln x` сохраняется;
- `gapShape` = k — гамма-промежутки со средним `ln x`: `var/mean² = 1/k`.

Результаты 2M-матрицы (5 сидов на строку):

| Режим | κ | k | twinIndex | var/mean² | n − π(x_max) |
|---|---|---|---|---|---|
| jump-twin | 0.5 | – | **1.346** (+1.3%) | 1.051 | −2816 |
| jump-cluster | – | 1.45 | 0.633 (−52%) | **0.696** (−2.4%) | +42 |
| **jump-corr** | 0.8 | 1.5 | **1.348** (+1.5%) | **0.738** (+3.6%) | **−48** |
| jump-twin-2C2 | 1.32 | – | 2.094 (+58%) | 1.138 | −2130 |
| реальные | – | – | 1.328 | 0.713 | — |

**Решёточная связка (`lattice6`)**: элементы >3 удерживаются в классе ±1 mod 6 (попадание на кратное трём перенаправляется +2, минимальный промежуток 4), инъекция близнецов — только из вычета 5 (пары 5→1; κ6 = 2.1 при k = 1.45). Результат: **mod6-гистограмма закрывается** — 52.0/24.0/24.0 против реальных 43.5/28.2/28.2 (без решётки 14.5/21.4/15.7), twinIndex 1.353 и var/mean² 0.708 одновременно в ~2% от реальных. Найденная цена: цепь состояний асимметрична (доля 5 mod 6 ≈ 0.657 против реальных 0.5003), поэтому решётка создаёт **ложный Δ₆ ≈ 628 тысяч против 634 у реальных (×1000)** — баланс вычетов оказывается независимым структурным параметром уровня решётки вычетов, не воспроизводимым правилами промежутков; плотность при этом держится в пределах 2.5%.

**Jumping champions** (`scripts/jumping-champions.mjs` → `results/jumping-champions.md`): чемпионы промежутков, пары (p, p+g) и сингулярный ряд. Замеры: чемпион реальных промежутков — 6 на всём диапазоне (доля 24.3% → 14.1% монотонно вниз, доля 30 растёт 0.9% → 3.6%); на рубеже x ≈ 1.74·10⁶ замерено перестроение топа — 12 обгоняет 2 и 4; переход 6→30 по эвристике `S(g)·exp(−g/ln x)` требует x ≈ 1.5·10³⁶ — вне вычислительного диапазона. Зато знаменитый эффект Харди–Литтлвуда на парах подтверждён точно: пар (p, p+30) уже больше, чем (p, p+6) — 437 109 против 327 265, отношение 1.336 при предсказанных 1.333 (0.2%); отношения пар/𝔖(g) ≈ 1.000 по всем g. Модели не воспроизводят ни чемпионов (baseline jump — чемпион «промежуток 1» с долей 8.85%, решётка завышает 6 вдвое: 30.8% против 14.1%), ни сингулярный ряд (пары 30/6 у моделей 0.77–1.00 против 1.336). После добавления `lattice30` champion-структура у модели появилась: доля 6 — 14.33% против реальных 14.11%, доля 30 — 4.49% против 3.61%, пары 30/6 — 1.535 против 1.336 (конечный кусок 𝔖-структуры воспроизводим, но с перелётом).

**Дивергенции второго плана** (`scripts/model-divergences.mjs` → `results/model-divergences.md`; 3 конфигурации × 5 сидов, «много запусков» — дивергенция = реальное значение вне ±2σ разброса по сидам). Найдено четыре новых расхождения, все вне модельного шума:

- **Автокорреляция промежутков**: реальная ρ1 = −0.034 (большие промежутки сменяются меньшими) против ~+0.005 у независимых скачков (z до −72);
- **Переходы последних цифр** (эффект Lemke Oliver–Soundararajan 2016): реальная диагональ a→a −32.8% против −21.6% у jump — матрицы переходов расходятся; решётка `lattice6` приближается (−33.3%, z = 5.7) — часть вычетной корреляции она ловит;
- **Рекордные промежутки**: реальный максимум 210 (C_g = 0.739, все рекорды совпали с известными таблицами — решето сверено); экспоненциальный хвост jump завышает (236 ± 13), гамма-хвост `gapShape` чинит рекорды автоматически (191 ± 10 / 192 ± 18 — в шуме);
- **Условная структура близнецов**: реальный средний следующий промежуток после 2 — 17.72 против безусловного 16.23 (+9%): близнецы у реальных простых — не независимые события; все модели дают ~16.1–16.8.

### Иерархия воспроизводимости (итог расследования «модель vs реальность»)

| # | Структура | Уровень | Воспроизводится |
|---|---|---|---|
| 1 | Плотность 1/ln x | калибровка Крамера | ✅ ядро |
| 2 | Близнецы (twinIndex) | промежутки | ✅ `twinRate` |
| 3 | Сгущения (var/mean²) | промежутки | ✅ `gapShape` |
| 4 | mod6-гистограмма | решётка вычетов | ✅ `lattice30` — до 0.1% от реальной (43.6/28.2/28.2) |
| 5 | Баланс вычетов (Δ₄ / Δ₆) | решётка вычетов | ⚠️ частично: Δ₄ воспроизводится `lattice30` (328 ± 1107 против реальных 504), ложный Δ₆ уменьшен вдвое (273k), но остаётся ×430 |
| 6 | Чемпионы промежутков, сингулярный ряд | произведения по всем малым простым | ⚠️ частично: `lattice30` воспроизводит чемпион-структуру (6: 14.33% против 14.11%) и завышает пары 30/6 (1.54 против 1.336); полный 𝔖-ряд — нет |

Каждый следующий уровень требует корреляций следующего порядка: правила промежутков и конечные решётки вычетов закрывают уровни 1–4 и частично 5–6; полный сингулярный ряд Харди–Литтлвуда (произведения по всем малым простым) конечными правилами промежутков не достигается.

Подробности и полные таблицы — `results/model-vs-reality.md`, `results/jumping-champions.md` и `results/model-divergences.md`. Связный пересказ с графиками — статья [`article/ARTICLE.md`](article/ARTICLE.md) (данные: `node scripts/article-data.mjs` → `results/article-data.json`; фигуры: `node scripts/make-figures.mjs`; валидация переноса: `node scripts/generalization.mjs` — решето до 10⁹, формальный фит κ/k бисекцией + координатным спуском, матрица переносов 10⁶/3.2·10⁷/10⁹). Итог валидации: параметры локальны по масштабу — twinIndex реальных масштабно-инвариантен (≈2C₂), дисперсия растёт с x (0.651 → 0.727 → 0.753), поэтому k ≈ 1/disp(x) «плывёт» с диапазоном; κ≈0.8 переносится, k — нет. Детрендированная антикорреляция промежутков реальных (ρ₁det ≈ −0.031…−0.055, бутстрап-CI не накрывает нуль) не воспроизводится ни одной конфигурацией (модели ≈ 0).

Тесты ядра (`npm test`, vitest): 23 проверки — детерминизм-регрессия эталонных прогонов, точные π(x) и максимальный промежуток решета, измеренные мишени всех исследовательских режимов, инварианты решёток — любое изменение ядра сверяется с реальными простыми за ~90 секунд.

## GPU-ускорение

`useGPUCalculations.ts` строит скалярные WebGL-кернелы (gpu.js):

- поэтапный **бинарный поиск** в кернелах вместо циклов по массивам
- average-кернел без промежуточных аллокаций
- валидация результатов через `Number.isFinite`
- **автоматический откат на CPU**: любая ошибка создания/выполнения кернела перехватывается, и расчёт выполняется на JS без изменения результатов

## Веб-интерфейс

Двухпанельный layout на весь экран: липкий сайдбар слева, графики справа.

**Сайдбар:**
- Статистика: `Number`, `Count`, `Probability`, а также `Skipped`, `Truncated`, `Time` (появляются, когда значения > 0)
- Кнопки: `List N` — сгенерировать одну последовательность длины N; `Generate Multiple` — несколько последовательностей с графиком среднего
- Прогресс-бар с процентами и счётчиком чисел/последовательностей во время генерации
- Настройки: `Logs` (логирование вычислений в консоль), `Tolerance` (1e-4, 1e-6, 1e-9 по умолчанию, 1e-10, 1e-12), `Seed` (splitmix32; последовательность k в Generate Multiple использует seed + k), `Sequences` (1–100), `Max` (1–100)
- Сгенерированная последовательность

**Графики:**
- **Ось X**: натуральные числа с шагом 5
- **Ось Y**: разница (количество псевдопростых − π(x) эталонных)
- Отдельный график на каждую последовательность (переключатель `Next →`) и общий график среднего; канвасы адаптивно масштабируются под размер окна
- **Gap Structure**: гистограмма промежутков выбранной последовательности (бар gap=2 выделен) + статистика — mean gap, twinIndex, gap=2 %, var/mean², mod6 0/2/4 %
- **Compare with real primes**: тумблер в Gap Structure — решето до x_max последовательности, на одном графике кривые `count ≤ x` (модель vs π(x)) и строка сравнения: π(x), twinIndex модель/реальные (×ratio), mean gap, mod6 реальных
- **Experiment Analysis**: средние кривые групп из `results/analysis.json` с полосами ±σ; тумблеры `Theory` (оверлеи Li(x)−π(x) и ±√π(x)) и `log x` (десятичная лог-шкала)

## CLI

```sh
npm run cli -- <command> [options]
# или напрямую:
node scripts/cli.mjs <command> [options]
```

### Команды

| Команда       | Описание                                                                  |
| ------------- | ------------------------------------------------------------------------- |
| `generate`    | Сгенерировать псевдопростую последовательность                             |
| `probability` | Посчитать вероятность включения-исключения для набора чисел                |
| `diff`        | Сравнить количество элементов последовательности с π(x) по шагам x         |
| `bench`       | Измерить производительность генерации и пересчёта суммы вероятностей       |

### Опции

| Опция                      | Описание                                                                    | По умолчанию |
| -------------------------- | --------------------------------------------------------------------------- | ------------ |
| `--count <n>`              | Длина последовательности                                                    | `20`         |
| `--tolerance <f>`          | Отсечение слагаемых с вкладом ниже f — главный регулятор точность/скорость  | `1e-9`       |
| `--sensitivity <n>`        | Предел мощности подмножеств включения-исключения                            | unlimited    |
| `--seed <n>`               | Seed PRNG — вывод воспроизводим                                             | `42`         |
| `--initial <a,b,…>`        | Начальные числа, целые ≥ 2                                                  | `2,3`        |
| `--mode <jump\|step>`      | Режим генерации (Крамер): jump — экспоненциальные скачки со средним ln(x), step — принятие при 1/ln(x) | `jump`       |
| `--jump-gap <round\|floor>`| Только jump: дискретизация промежутка; floor — `1 + floor(Exp(ln x − 1/2))` (несмещённая), round — `max(1, round(Exp(ln x)))` | `round`      |
| `--twin-bias`              | Только step: буст вероятности кандидата +2 на 2C₂ с компенсацией плотности (twins Харди–Литтлвуда) | выкл.        |
| `--no-track-probability`   | Не обновлять вероятность включения-исключения по мере генерации (на генерацию не влияет) | выкл.        |
| `--numbers <a,b,…>`        | Только для `probability`: явный набор чисел (без генерации)                 | —            |
| `--step <n>`               | Только для `diff`: шаг x                                                    | `5`          |
| `--format <text\|json\|csv>`| Формат вывода                                                              | `text`       |
| `--max-combinations <n>`   | Предохранитель: прервать при превышении числа комбинаций                    | `5e8`        |

### Примеры

```sh
npm run cli -- generate --count 20 --seed 42
npm run cli -- generate --count 50 --tolerance 1e-9 --mode step --format csv
npm run cli -- probability --numbers 2,3,5,7,11
npm run cli -- probability --numbers 2,3,5,7,11 --sensitivity 3 --format json
npm run cli -- diff --count 100 --seed 1 --step 5
npm run cli -- bench --count 500 --seed 7
```
