# Simple Numbers

Экспериментальный инструмент для исследования простых чисел: изолированное ядро на чистом JavaScript (Node + браузер), CLI для генерации и анализа последовательностей и веб-приложение на Vue 3 с GPU-ускорением через WebGL.

## Обзор

Приложение генерирует «псевдопростые» последовательности на основе вероятностной модели: для текущей последовательности вычисляется вероятность `P` того, что случайное целое число не делится ни на одно из её чисел (формула включения-исключения). Эта вероятность управляет генерацией следующего числа. Псевдопростые принимаются без проверки на простоту — расхождение с настоящими простыми числами (`π(x)`) анализируется по графикам и таблицам разниц.

## Возможности

- **Ядро без зависимостей** (`src/core/*.mjs`): одно и то же вычислительное ядро работает в Node (CLI) и в браузере
- **Генерация последовательностей**: два режима — `jump` (случайный интервал `[min, min + 1/P]`) и `step` (кандидат +1 принимается с вероятностью `P`)
- **Воспроизводимость**: детерминированный PRNG (mulberry32) — результат однозначно определяется seed
- **CLI**: команды `generate`, `probability`, `diff`, `bench` с выводом в `text`, `json` или `csv`
- **Веб-интерфейс**: двухпанельный layout, статистика в реальном времени, прогресс генерации, графики распределения разниц (по последовательностям + средний)
- **GPU-ускорение**: WebGL-кернелы (gpu.js) с автоматическим откатом на CPU при любой ошибке

## Технологический стек

- **Ядро**: чистый JavaScript (ESM, `.mjs`) с типами `.d.mts`
- **Frontend**: Vue 3 (Composition API, TypeScript в composables/utils)
- **Build**: Vite 7, `sass-embedded`
- **GPU**: gpu.js ^2.16.0 (WebGL)
- **Node**: `^20.19.0 || >=22.12.0`

## Математическая основа

### Вероятность (включение-исключение)

Для последовательности простых `p₁, p₂, …, pₙ`:

```
P = 1 − Σ(±1 / (p₁ × p₂ × … × pₖ))   по всем непустым подмножествам
```

Знак слагаемого определяется мощностью подмножества: нечётная — плюс, чётная — минус. Пример для `{2, 3}`:

```
P = 1 − (1/2 + 1/3 − 1/(2×3))
```

### Оптимизации вычисления суммы

- **Компенсированное суммирование Ноймайера**: слагаемые порядка `1e-16` не теряются при накоплении суммы
- **Отсечение по tolerance**: подмножество пропускается, как только произведение превышает `limit = 1 / tolerance` (вклад меньше tolerance); счётчик пропусков доступен как `skipped`
- **Ограничение sensitivity**: опциональный предел мощности подмножеств в слагаемых (по умолчанию не ограничен)
- **Бюджеты комбинаций**: `maxCombinations` — общий предохранитель; `maxCombinationsPerPrime` (30 000 000) — лимит на одно добавленное число. При срабатывании добавление помечается `lastAddTruncated`, а UI показывает предупреждение о сниженной точности

### Генерация последовательности

- `mulberry32(seed)` — детерминированный PRNG
- **jump**: `next = current + round(min + random() / P)` — случайный интервал, где больший `P` даёт меньший шаг
- **step**: кандидат `+1` принимается, если `random() ≤ P`
- Начальная последовательность: `[2, 3]`; числа принимаются как «псевдопростые» без проверки простоты

### Эталон π(x)

Для сравнения используется решето Эратосфена (`primeCountPrefix`, `Uint32Array` + `Uint8Array`) — решето применяется **только** к эталонным количествам простых, не к псевдопростым.

## Эксперимент: отклонение псевдопростых от π(x)

### Методология

`node scripts/run-experiment.mjs` прогоняет матрицу последовательностей и сохраняет rich JSON (sequence + points разниц + статистика) в `results/`; скрипт возобновляем — готовые прогоны пропускаются. `node scripts/analyze-results.mjs` группирует прогоны по режиму/tolerance, выравнивает общую сетку x и считает среднюю кривую разниц ±σ по seeds, регрессионный наклон и кросс-режимные сравнения. Итог: `results/analysis.json` + `results/analysis.md`.

Базовая матрица: якорь (jump, seed 42, 100k @1e-10), 4×jump и 4×step по 300k @1e-10 (seeds 1–4), 2×50k @1e-11. Время: jump 300k ≈ 50с, step 300k ≈ 25с, 50k @1e-11 ≈ 140–300с.

Калиброванная матрица (`node scripts/run-experiment.mjs --calibrated`): якорь + 4×cal-jump + 4×cal-step 300k @1e-10 (seeds 1–4) в режиме `calibrated: true, trackProbability: false` — без feedback-механизма вероятности, каждый прогон ≈ 0.1с.

Долгая калиброванная матрица (`node scripts/run-experiment.mjs --long`): 5×cal-jump + 5×cal-step по 2M @1e-10 (seeds 1–5, xStep 200) — x до ≈ 32.5M, π(x) ≈ 2.0M, генерация 0.3–0.9с на прогон.

### Ключевой результат

Средний график псевдопростых **не совпадает** с π(x) — смещение систематическое (~4–5σ по разбросу seeds) и монотонно растёт с x:

| Режим | count / tolerance | Средняя разница на конце | Отклонение |
| --- | --- | --- | --- |
| jump | 300k @1e-10 | +43 083 (x ≈ 3.45M) | **+17.4%** |
| step | 300k @1e-10 | −22 867 (x ≈ 4.53M) | **−7.2%** |
| step | 50k @1e-11 | −10 793 (x ≈ 0.76M) | −17.8% |

### Механизм: произведение Мертенса, а не 1/ln x

Включение-исключение сворачивается в точную рекуррентность `P_new = P_prev × (1 − 1/p)`, то есть после накопления множества «простых до x» вероятность модели равна ∏(1 − 1/p). По третьей теореме Мертенса:

```
∏(1 − 1/p) ~ e^(−γ) / ln x ≈ 0.5615 / ln x,   а плотность простых = 1/ln x (ПТС)
```

Модель требует отсутствия делителей среди **всех** накопленных чисел до x, тогда как простота требует лишь отсутствия делителя до **√n** (критерий Лежандра) — избыток жёсткости и даёт постоянный множитель e^(−γ) ≈ 0.5615. Отсечение по tolerance выбрасывает хвост ряда включения-исключения и **поднимает** вероятность выше Мертенса: tolerance интерполирует между «принимать всё» (P → 1) и Мертенсом (P → 0.5615/ln x), поэтому ужесточение tolerance не приближает к π(x), а увеличивает недобор (−7% при 1e-10 → −18% при 1e-11). Режим jump добавляет второй независимый фактор: равномерный выбор в диапазоне 1/P даёт средний скачок 1/(2P) → плотность ×2 → перебор.

### Калибровка Крамера: возврат к π(x)

Если смещение создаётся механизмом вероятности, прямая калибровка по ПТС должна его убрать. В ядре есть режим `calibrated` (флаг `--calibrated` в CLI): step принимает кандидата при `random() < 1/ln(x)`, jump делает экспоненциальный скачок со средним ln(x) — модель Крамера (1936):

| Режим | count / tolerance | Средняя разница на конце | Отклонение | σ по seeds vs √π(x) |
| --- | --- | --- | --- | --- |
| cal-jump | 300k @1e-10 | −481 (x ≈ 4.25M) | **−0.16%** | ×0.8 |
| cal-step | 300k @1e-10 | +385 (x ≈ 4.24M) | **+0.13%** | ×1.1 |
| cal-jump | 2M @1e-10 | −2854 (x ≈ 32.5M) | **−0.14%** | ×0.4 |
| cal-step | 2M @1e-10 | +2388 (x ≈ 32.4M) | **+0.12%** | ×0.8 |

Смещение исчезает (±0.2% против +17.4%/−7.2%), наклон регрессии — нулевой, а cross-seed σ возвращается к порядку предсказания Крамера √π(x): ×0.8–1.1 против ×16.6/×10.1 у базовых режимов — избыточная дисперсия псевдопростых создаётся именно self-feedback механизма вероятности, а не природой простых.

Масштабная проверка (`--long`, 2M чисел): при росте x в 7.6 раза (4.25M → 32.5M) относительное отклонение **не накапливается** (−0.16% → −0.14%, +0.13% → +0.12%), наклон остаётся нулевым. Остаточные смещения стабильны и объяснимы по знаку и порядку: cal-step +2388 близок к избытку Li(x) над π(x) — чистый Крамер с плотностью 1/ln x интегрируется в Li(x), а реальный π(x) при x ~ 3×10⁷ отстаёт от Li на тысячи; cal-jump −2854 получает вклад от дискретизации `max(1, round(Exp))` — ~2.9% нулевых скачков становятся единичными, увеличивая средний промежуток (≈ −0.17% плотности), что перекрывает Li-избыток. Флуктуации на 2M остаются суб-пуассоновскими (×0.4–0.8; сама σ-оценка по 5 сидам имеет ~25% погрешность), а cal-jump и cal-step расходятся линейно, ~+160 на каждый 1M x — константа расхождения совпадает с 300k.

Вывод: модель точно воспроизводит решето Эратосфена как процесс (плотность выживших после всех просеиваний = произведение Мертенса), но не функцию распределения простых — для последней нужна калибровка Крамера. При этом тонкая структура не воспроизводится ни базовыми, ни калиброванными режимами: у реальных простых twinIndex = 2C₂ ≈ 1.32, у калиброванных — 0.87 (jump) / 0.94 (step), а дисперсия промежутков 1.00/0.94 против 0.66 у реальных — «близнецовый» избыток и сгущения реальной последовательности остаются вне и пуассоновской, и мертенсовской моделей. Прогон 2M подтверждает это на 10× данных: twinIndex 0.89 (jump) / 0.94 (step) против 1.33 у реальных, дисперсия промежутков 1.00/0.95 против 0.71, mod6-структура реальных промежутков (43.5/28.2/28.2) отсутствует (≈14/18/16).

## GPU-ускорение

`useGPUCalculations.ts` строит скалярные WebGL-кернелы (gpu.js):

- поэтапный **бинарный поиск** в кернелах вместо циклов по массивам
- average-кернел без промежуточных аллокаций
- валидация результатов через `Number.isFinite`
- **автоматический откат на CPU**: любая ошибка создания/выполнения кернела перехватывается, и расчёт выполняется на JS без изменения результатов

## Веб-интерфейс

Двухпанельный layout на весь экран: липкий сайдбар слева, графики справа.

**Сайдбар:**
- Статистика: `Number`, `Count`, `Probability`, а также `Skipped`, `Truncated`, `Time` (появляются, когда значения > 0)
- Кнопки: `List N` — сгенерировать одну последовательность длины N; `Generate Multiple` — несколько последовательностей с графиком среднего
- Прогресс-бар с процентами и счётчиком чисел/последовательностей во время генерации
- Настройки: `Logs` (логирование вычислений в консоль), `Tolerance` (1e-4 … 1e-15), `Sequences` (1–100), `Max` (1–100)
- Сгенерированная последовательность

**Графики:**
- **Ось X**: натуральные числа с шагом 5
- **Ось Y**: разница (количество псевдопростых − π(x) эталонных)
- Отдельный график на каждую последовательность (переключатель `Next →`) и общий график среднего; канвасы адаптивно масштабируются под размер окна

### Команды

| Команда       | Описание                                                                  |
| ------------- | ------------------------------------------------------------------------- |
| `generate`    | Сгенерировать псевдопростую последовательность                             |
| `probability` | Посчитать вероятность включения-исключения для набора чисел                |
| `diff`        | Сравнить количество элементов последовательности с π(x) по шагам x         |
| `bench`       | Измерить производительность генерации и пересчёта суммы вероятностей       |

### Опции

| Опция                      | Описание                                                                    | По умолчанию |
| -------------------------- | --------------------------------------------------------------------------- | ------------ |
| `--count <n>`              | Длина последовательности                                                    | `20`         |
| `--tolerance <f>`          | Отсечение слагаемых с вкладом ниже f — главный регулятор точность/скорость  | `1e-9`       |
| `--sensitivity <n>`        | Предел мощности подмножеств включения-исключения                            | unlimited    |
| `--seed <n>`               | Seed PRNG — вывод воспроизводим                                             | `42`         |
| `--initial <a,b,…>`        | Начальные числа, целые ≥ 2                                                  | `2,3`        |
| `--mode <jump\|step>`      | Режим генерации                                                             | `jump`       |
| `--calibrated`             | Калибровка Крамера: step принимает при 1/ln(x), jump — экспоненциальные скачки со средним ln(x) | выкл.  |
| `--track-probability`      | Только с `--calibrated`: продолжать скармливать псевдочисла сумме вероятности (медленно) | выкл.  |
| `--numbers <a,b,…>`        | Только для `probability`: явный набор чисел (без генерации)                 | —            |
| `--step <n>`               | Только для `diff`: шаг x                                                    | `5`          |
| `--format <text\|json\|csv>`| Формат вывода                                                              | `text`       |
| `--max-combinations <n>`   | Предохранитель: прервать при превышении числа комбинаций                    | `5e8`        |

### Примеры

```sh
npm run cli -- generate --count 20 --seed 42
npm run cli -- generate --count 50 --tolerance 1e-9 --mode step --format csv
npm run cli -- probability --numbers 2,3,5,7,11
npm run cli -- probability --numbers 2,3,5,7,11 --sensitivity 3 --format json
```
